## 4. The Three Patterns Worth Surfacing for Process

Briefly, because the question was about requirements/functionality, not process — but these are visible in the data and worth recording.

### 4.1 The sibling-quartet inline-fix-and-walk pattern (F6 → F7 → F8 → SKILL.md)

Four Hermes-integration contract bugs were discovered and closed in a single session via the inline-fix-and-walk loop. The pattern: live walk surfaces a contract mismatch → root-cause investigation → minimal-scope fix → regression tests → live re-walk → next bug surfaces. Each fix was justifiably inline (small surface, single boundary layer, live-walk verification absorbed CR cost) and all four shipped with §5.12 self-audit cadence rather than full MANDATORY-CR.

**Implication:** Phase 3.5 walks for Hermes-touching stories should explicitly enumerate ALL contract boundaries (routing, transport-security, application-translation, skill-loader, tool-calling) and verify each one live. The F11 carry-forward represents the one boundary the sibling-quartet didn't reach because Hermes's request shape requires tool-calling support that doesn't exist yet on the server.

### 4.2 The schema-reality reframe pattern

Three times in Epic 6, an invented contract was retired in favor of a real one:

- **Story 6-0:** Story 5-4's invented `hermes-config/config.yaml` schema retired; replaced with real Hermes schema from mirrored docs.
- **Story 6-3:** The epic spec's invented "Hermes inbound HTTP webhook" for notification delivery retired; replaced with pull-based MCP (`pull_pending_notifications` + `ack_notification`).
- **Story 6-5:** The epic spec's "Hermes-cron job runs at 08:00 with-agent and posts to Discord" trigger side deferred; mailbot-api ships `compose_digest` verb + `finalize_digest_delivery` sweeper; consumer is carry-forward.

**Implication:** The dev-codeable side of mailbot-api is now substantially ahead of the Hermes-side integration cadence. The Hermes-cron-skill bundle work needs to be a first-class block of work in Epic 7 — or, more honestly, as Story 6-9 / Story 6-10 follow-ups that close out Epic 6 properly rather than waiting for Epic 7 to absorb it.
