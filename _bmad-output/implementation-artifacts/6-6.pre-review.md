## 3. Adversarial self-review

- **[HIGH]** `mailbot_api/worker.py` `_drainer_heartbeat_loop` — the heartbeat polls `drainer_task.done()` to decide outcome. There's a closure-binding subtlety: `drainer_task` is captured BEFORE it's assigned (the var binds late). Python's lexical scoping makes this work because the closure looks up `drainer_task` at call time, not definition time — but a reviewer may flag the construction order as fragile. Disposition: works correctly per `test_worker_main_integration.py` (all 8 components land heartbeats). Consider refactoring to pass the task as a parameter for clarity.
- **[MEDIUM]** `mailbot_api/worker.py` — `oauth_token_refresh` interval task is NEW and not in the canonical AC text. It's REQUIRED by the OutlookGraphWriteAdapter's sync-callable contract (the adapter wants `Callable[[], str]` but `get_access_token` is async). I added the token refresher as a scheduler-driven task; without it, the adapter would dispatch with a stale cell value or empty string. A reviewer may push back: "this isn't in the ACs." The defense: the AC requires Tier-2/3 SEND to work end-to-end; that REQUIRES a fresh access token; the refresher is the wiring that makes the requirement true. Documented in Dev Notes + Completion Notes.
- **[MEDIUM]** `_CachedAccessToken` is a module-level mutable container (a dataclass instance, not strictly module-level — closed over by `_worker_main`'s local scope). The §5.7 Posture Audit normally flags module-mutable containers; this one is process-scoped + single-writer (only `_refresh_access_token_cache` mutates it). Acceptable per Python overlay (Final[Mapping] is not applicable to a write-once cache; the value rotates).
- **[MEDIUM]** `test_worker_main_integration.py` boots the actual `_worker_main` but cancels the asyncio task to terminate (because `_worker_main` waits on its own `shutdown_event`). The Windows signal-handler path (no `loop.add_signal_handler`) means SIGTERM doesn't have a test surface here. A reviewer may push back: "no test for SIGTERM clean shutdown." The defense: `test_drainer_shutdown_event_stops_loop` covers the shutdown_event path; the SIGTERM handler is a thin one-line `shutdown_event.set()` wrapper — minimal logic, low risk.
- **[MEDIUM]** `OAUTH_STATE_ACCESS_TOKEN_SELECT` SQL constant added to `db/queries.py` with `# noqa: S105` (false-positive password detection). A reviewer may suggest renaming to avoid the suppression — but the SQL is a legitimate column-name query, not a credential. Acceptable.
- **[LOW]** `_make_sync_iteration_factory` returns a closure capturing `state`; the scheduler wrapper writes a heartbeat AFTER `_run_sync_iteration` ALSO writes one. Result: two writes per sync iteration (both upsert on the same component key, second-write wins). Functionally fine (last-write-wins matches outcome); slight overhead per iteration. Documented in the function docstring.
- **[LOW]** `mypy --strict` required loosening the scheduler signature from `Awaitable[None]` to `Awaitable[object]` because `run_drain_loop` returns `DrainLoopResult` and `cooling_off_tick` returns `int`. Trade-off: lose the type-level "your coro returns None" contract; gain compatibility with non-None-returning coros. Documented in Completion Notes.
- **[LOW]** No stress test (100 sequential drains). Defense in Completion Notes: existing scheduler tests run 2-4 iterations over 0.1-0.2s windows; UPSERT-on-conflict is structurally state-leak-proof; a 100-iteration test adds duration without coverage. A reviewer may push back; the response is principled.
- **[INFO]** `docs/architecture-notes.md` is a new file outside `_bmad-output/`. Project convention may or may not have a preferred docs home — bias toward `docs/` for architecture-spanning memos.
- **[INFO]** Pre-existing markdownlint warnings in the story file are out of scope per PORTING.md.
