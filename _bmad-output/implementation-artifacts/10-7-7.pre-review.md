## 3. Adversarial self-review

- **[MEDIUM] router.py `_max_repeated_tool_invocation`** — counts the MOST-repeated (name,args) across the WHOLE transcript, not just the model's latest choice. A user legitimately asking two separate real turns that each repeat could accumulate. Mitigated: Hermes opens a fresh transcript per user turn, and threshold 4 within one turn is far above any legitimate same-args repeat. Accept.
- **[MEDIUM] AC-1 NULL posture** — rows synced before migration 029 carry `is_read=NULL` and are invisible to `unread_only` until re-synced. On first live walk the inbox may show FEWER unread than Outlook until a full delta re-sync repopulates. This is honest-by-design but could read as "unread filter broken" at the walk. Documented in the migration + flagged for the AC-7 walk. Accept-with-rationale.
- **[LOW] threshold constant** — `_REPEAT_INVOCATION_THRESHOLD=4` is a guess calibrated to the observed 60× storm; if a legitimate agent pattern needs ≥4 identical calls it would trip. No such pattern known (identical args = no new information). Accept; revisit if the walk surfaces a false positive.
- **[LOW] guard placement vs sensitivity gate** — the storm guard fires BEFORE the sensitivity precondition. A storm of a sensitive-email tool-call terminates without ever reaching the sensitivity gate. This is SAFE (terminal refusal, no action, no API call) but means the audit row is `no_progress`, not `sensitivity_*`. Acceptable — the guard is a pure loop-terminator; it cannot authorize anything.
- **[LOW] `_normalize_tool_args` fallback** — non-JSON args fall back to a stripped raw string for the key. Two malformed-but-different arg strings won't collapse, but that's the safe direction (under-counts, never over-counts → never a false storm). Accept.
