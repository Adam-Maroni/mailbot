## Dev Notes

### Option γ entry-point contract (why this reframe preserves the audit invariants)

Per `_bmad-output/implementation-artifacts/epic-9-5-run-flags.md` § "Option γ viability confirmed 2026-07-03" (reading the code at [`mailbot_api/router/audit_vocab.py:78-89`](mailbot_api/router/audit_vocab.py#L78) + [`mailbot_api/router/router.py:266-296`](mailbot_api/router/router.py#L266)):

- **`OVERRIDE_SLASH_ONE_SHOT`** fires whenever `_oneshot_engaged=True` during `ask_router` (router.py:270-272). The flag becomes True when `ask_router` peeks a value in the one-shot session slot. **The slot is set by `set_model_oneshot(model=...)` regardless of caller — Hermes-chat MCP invocation, direct MCP CLI, hypothetical Discord slash all populate the same slot.** The `SLASH` name is historical (Story 9-3-era naming when the plan was still "Hermes owns the `/model` slash surface"), not surface-bound. The `audit_vocab.py:79` docstring reads verbatim: *"Adam typed `/model <task> <model>` in a Hermes chat session; the session-scoped one-shot flag was consumed on this dispatch."* — matches the Option γ entry exactly.
- **`OVERRIDE_SLASH_PERSISTENT`** fires whenever `task_type in policy.overrides_applied` at cache-hit-narrowed dispatch (router.py:287-288). `overrides_applied` is populated when `router/policy.user-overrides.yaml` has a task entry, which is what `set_model_persistent` writes — caller-agnostic.
- **`SENSITIVITY_GATE_REFUSED`** fires at the pre-dispatch sensitivity check inside the router, BEFORE model selection. Doubly caller-agnostic — the gate fires on the routing state (`sensitivity=confidential` on the email row + the request's downstream model being non-Claude), not on how the request entered.

**Net:** Story 9-2's audit vocab needs zero changes for Option γ. AC-1/AC-2/AC-3 acceptance thresholds preserve byte-identical.

### Why Hermes-chat MCP invocation works when Discord slash didn't (the architectural block that Run 1 discovered)

Per Run 1 finding (see `epic-9-5-run-flags.md`):

1. Hermes's `discord_platform.adapter._register_slash_commands()` (line 2963 in the container's copy) registers 26+ Discord slash commands at Gateway startup, including its own `/model name:<name>` that switches **Hermes's LLM** (not MailBot's router).
2. `_safe_sync_slash_commands()` (line 1131) tears down any externally-registered Discord slash commands that don't match Hermes's fingerprint on each Gateway restart. Story 9.5.1's `scripts/register_discord_commands.py --apply` registration would not survive Hermes's next restart.
3. Even if the command survived, Discord routes interactions to Hermes's Gateway consumer — which has no handler bridging Discord subcommand interactions to MailBot's MCP verbs.

**But** Hermes's MCP-tool discovery (`hermes-config/config.yaml` lines 94-106) auto-registers all 25 MailBot verbs into Hermes's LLM's tool registry with `mcp_mailbot-api_<verb>` prefix. Hermes's chat LLM CAN fire those tools when Adam asks in natural language — that's the whole design. **Option γ uses this pre-existing wire, no new infrastructure.**

### AC-3 sensitivity-gate contract (NFR-PRIV-2 live verification)
