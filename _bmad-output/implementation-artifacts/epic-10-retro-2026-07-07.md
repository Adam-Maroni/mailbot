## 8.5 Design spec — sensitivity-refusal UX (Adam-directed, feeds action B7)

**Problem (F-10-5-6, MEDIUM):** the router's refusal is correct (`sensitivity_blocks_api`, privacy invariant held), but what reaches Discord is a raw HTTP-502 retry ladder that also leaks the full Graph email id — not the documented graceful prompt.

**Architectural decision — structured refusal envelope, rendered at the boundary** (reuses the Epic 6.5 `recovery_action` / Rule S shape). Rationale:

1. **Separation of concerns:** router *decides* (machine code + typed facts: email_ref, task, classification, reason); the chat boundary *speaks*. No presentation logic behind the privacy boundary; wording survives a channel change.
2. **Leak fixed by construction:** a typed envelope has an explicit field allow-list — the internal Graph email id is simply not a printable field, so F-10-5-6's id-leak becomes structurally impossible rather than scrub-dependent.
3. **Fixes the class, not one string:** the "raw 502" arises because a structured refusal became an *exception* on the chat path. Carrying refusals as errors-as-data (AR-PAT-4) so the boundary renders a refusal *as a refusal* benefits every refusal on that path.

**Message contract — four beats: name the state → consequence in user terms → the one action that works → expectations.** No trace, no internal id, no dead-end instruction.

- **Sensitive:** "⚠️ That email is classified sensitive. Drafting/summarizing would send its contents to Claude's cloud API — I've held off, nothing left your mailbox. To go ahead this once, reply **'yes, escalate'** (authorizes this one email, this one task, 10 minutes)."
- **Confidential:** "🔒 Classified confidential. No cloud override exists — by design. Read it in Outlook." (offers NO escalation, because none exists)
- **Not-yet-classified (`sensitivity_not_classified`):** "⏳ Not sensitivity-classified yet. The ingest worker does this automatically within minutes — try again shortly." (does NOT suggest `mailbot rederive` — currently crashes, F-10-6-3)

**Load-bearing rule:** the message may only offer actions that actually work. This is why B7 binds F-10-5-6 to **F-10-5-7 (HIGH — sensitive escalation broken by construction: token minted without confirmation, bound to wrong session identity, never attaches, one attempt bricks the session):** a message promising "yes, escalate" while escalation is broken is worse than the 502 — it lies. Fixing the escalation path in the same story is what earns that sentence. Cluster B also owns F-10-5-5 (self-mint without confirmation), which is part of making "yes, escalate" a genuine user-gated event.

## 8.6 Design spec — per-answer cost + model footer (Adam-directed, feeds action B8)

**Ask (Adam):** after each answer the bot returns (1) which LLM model answered, (2) exact cost of that request + current month usage + "current Anthropic API credit" — with the explicit requirement that cost be **exact, requested from Anthropic, not approximate**.

**Hard reality (from durable memory `feedback_anthropic_spend_source_of_truth.md`, verified twice in Epic 9.5):**

- Anthropic's **per-message API returns token counts, not dollars** — there is no per-call price to "request". Dollars are always computed = tokens × published price.
- Exact aggregate billed dollars live behind **`GET /v1/organizations/cost_report`, an Admin-API endpoint** that 401s the workload key; this solo Console org cannot mint an Admin key (admin-keys page 404s). Structurally unavailable on this account.
- No API on this account returns **prepaid balance / remaining credit** at all.

**Adam decisions (this retro):** (cost source) exact vendor tokens × A2-verified prices; (credit line) drop "credit," show month-to-date + cap headroom; (surface) footer on every answer.

**Design — the number is exact, and provably not the estimator that burned us in 9.5.3:**

- `router_calls` already stores per-call `tokens_in` / `tokens_out` / `cached_tokens_in` (**vendor-exact**, from the Anthropic response `usage` block) + `model_chosen`. Month aggregation queries already exist (`ROUTER_CALLS_SPEND_SINCE` etc.).
- Cost = those exact tokens × the **A2-corrected published prices** in `pricing.py` (opus $5/$0.5/$25, haiku verified; exact-value regression pins added in 9.5). Accurate to the cent; diverges from Anthropic's own bill only if a published price changes without the constant being updated.
- **Pricing-freshness guard (load-bearing, enforces the durable rule in code):** if `pricing.py` still carries a `PLACEHOLDER` marker or its verified-on date is stale, the footer **degrades to tokens-only** and shows no dollar figure — never a dollar number it can't stand behind. This is the 9.5.3 "$36 vs $13" lesson as a code invariant, not a habit.
- Rename/clarify: the stored column is `cost_usd_estimated` but is now "exact-tokens × verified-price" — the story should reconcile the naming so the footer isn't labeled "estimated" when it isn't (or keep the column, label the footer honestly).

**Footer shapes:**

- Paid (Claude) answer: `🤖 haiku-4.5 · this reply: $0.0041 (1,240 in / 380 out) · July: $27.14 of $30 cap`
- Free local answer: `🤖 qwen (local, free)` (most of the volume; no dollar noise)

**Three honest departures from the literal ask — each forced by the account, documented so nobody reads the footer as more than it is:**

1. "request the API for exact per-request cost" → Anthropic returns exact **tokens**, not per-call dollars; exact-tokens × verified-price is the faithful realization.
2. "current Anthropic API credit" → no balance API exists on this org; replaced by month-to-date + cap headroom (computable, honest).
3. Vendor-billed aggregate truth is Admin-gated and unreachable here. **Upgrade path:** if Anthropic ever opens the Admin-keys page for Adam's org, the month-to-date line can be swapped from computed-from-tokens to `cost_report` vendor-billed truth — same footer, better source.

**Sequencing:** B8 lands **after B2** (July re-derive at corrected pricing) so the very first month-to-date figure the footer ever shows is already honest (~$26/$27, not the ~$70 inflated ledger).

## 8.7 Design spec — slash-syntax resolution (Adam-decided, feeds action B9, resolves F-10-5-1)

**Problem (F-10-5-1, HIGH — arguably charter-level):** the ENTIRE documented MailBot slash surface (README:188-207, incl. load-bearing `/cancel` + `/confirm`) never reaches the agent. Root cause is architectural, not a missing registration: **Discord reserves the `/` prefix for application commands, and the Hermes runtime — which sits ABOVE MailBot in the Discord layer — owns that namespace.** Any `/command` either collides with a Hermes-native command (`/model` opens Hermes's own model-picker UI; `inspect_policy` never fires) or bounces "Unknown command." Confirmed in `hermes-config/config.yaml:116-162`: Hermes registers Discord slash commands at runtime via the Developer Portal, not via MailBot config; MailBot verbs are MCP-dispatchable but have no reachable slash trigger.

**Decision (Adam, this retro): drop the `/command` metaphor entirely; move to plain natural language.** This is not building a new mechanism — the walk proved plain text ALREADY works (`spend month`, `cancel 14`, `mute newsletter` all dispatched correctly once the slash was dropped). B9 makes the documentation honest about how the product actually works, and removes the collision surface permanently (there is no prefix to collide).

**Load-bearing constraint — NL for reads, deterministic recognized-phrases for control verbs.** Two tiers:

- **Read/status/discovery intents** (spend, policy table, mute list, digest): free NL is ideal — agent parses intent and dispatches. No downside.
- **Control verbs that touch the mailbox or the kill-switch** (`cancel <id>`, `confirm`, `pause`, `resume`): must dispatch via a **deterministic recognized-phrase layer** (small exact-match phrase set → exact verb), NOT free-form LLM interpretation. Rationale: free interpretation of "cancel the thing I set up" re-opens the F-10-5-10 false-narration class (agent asserting outcomes it hasn't observed). Abort/pause/confirm must be reliably understood, not usually understood.

**Discoverability tie-in:** the B7 structured refusal envelope (`user_facing_guidance`) is the delivery vehicle — refusals/ambiguous requests surface the exact working phrase at the moment of need ("to abort this, type: cancel 14"), replacing the dead slash table as the way users learn the syntax.

**Scope:** charter-level README rewrite (removes the slash table §188-207, rewrites §69-107 write examples, the error-table fix cells that cite `/pause`/`/resume`/`/budget reset`/`/confirm`, and the §386 limitation bullet) + the recognized-phrase dispatch layer for control verbs. Likely its own story within Cluster B / a charter-rewrite story at 10.5 filing. Note: this SUPERSEDES the interim README honesty note ("type these WITHOUT the leading `/`") that 10-5/10-6 added — that note documented the workaround; B9 makes NL the actual contract.
