## Story

## Cluster & Findings

**Cluster E — must-fix. Findings: F-10-3-1 HIGH (the R4 target), F-10-3-2 HIGH. Includes retro §8.6 design (B8): the per-answer cost+model footer.** Epic 10's qwen audit (retro §5.4) found degraded-mode debt taxing the whole epic — a stuck inflated cost counter forced an operator reset, killed a scheduled digest, and made a fault row un-inducible.

- **F-10-3-1 HIGH — stuck degraded on the inflated counter.** Degraded mode tripped `2026-07-03T14:41:24Z` and stuck (~2.6 days at the 10-3 audit): `mailbot status` read `month: $70.2359 / $30.00 cap (234.1%)`, `degraded mode: yes`. The tripping counter is the **local estimator**, whose July numbers are known-inflated by the pre-A2 3× Opus placeholder (opus `anchor_calibrated_eval` alone carries **$62.5845 estimated** across 197 calls). The Adam-read Anthropic **Console total for all of July was ~$26** (9.5.4 D1 reconciliation). Under corrected A2 pricing the honest July counter is **~$26 < $30** → degraded mode would NOT be active at all. The $30 cap is MailBot's own `MONTHLY_HARD_CAP_USD` (`budget.py:37`), distinct from the $35 Anthropic Console cap the 9.5.x docs cite (amendment A1 corrected the earlier $35/$30 conflation — finding strengthened). Historical July rows retain their inflated estimates post-A2, so the degraded trip persists until month-rollover (Aug 1) or manual reset regardless of real spend.
- **F-10-3-2 HIGH — qwen can't serve `chat_completions_tool_call`, 18/18 fail.** While degraded, Hermes tool-calling chat turns dispatched to qwen fail outright (`outcome=failed`, 0 tokens, 0 ok / 0 retry_recovered across the 18 rows: 12 `degraded:…` + 6 `slash_command:one_shot:adam`, window 07-03→07-06). Root cause: `OllamaAdapter.call_with_tools` (`models.py:403-422`) unconditionally raises `AdapterProviderError("tools_unsupported")`, and the degraded-mode demotion at `dispatch_tool_call` (`router.py:1846-1865`) sends the tool-call to qwen anyway. The docstring at `router.py:1703-1707` calls this "intentional" cost-shedding — but the user-facing effect is the Discord surface degrading from *cheaper answers* to *no tool answers*, which is NOT the cost-shedding contract's intent (HIGH, user-facing). No stable error code surfaces — just opaque `failed` rows.

**Includes retro §8.6 (B8) design — the per-answer cost+model footer.** After each answer, show (1) which model answered, (2) the exact cost of that request + month-to-date usage vs cap. Adam-decided at the retro: cost from **exact vendor tokens × A2-verified `pricing.py` prices** (NOT the old estimator); **drop the "credit" line** (no balance/remaining-credit API exists on this org) → show **month-to-date + cap headroom** instead; footer on every answer.

See `10-3-walk-evidence.md`, `epic-10-retro-2026-07-07.md` §5.4/§8.6 + R4/B2, and durable memory `feedback_anthropic_spend_source_of_truth.md`.
