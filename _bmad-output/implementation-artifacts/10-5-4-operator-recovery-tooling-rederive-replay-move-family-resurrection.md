# Story 10.5.4: Operator recovery tooling — rederive, replay, move-family resurrection

Status: done

## Story

As Adam,
I want the documented recovery tools to actually work — `mailbot rederive` runs without crashing, `replay` handles move-induced `target_deleted`, and a soft-deleted move-family email can be resurrected — plus the retained 10-1 walk subject repaired as the verification,
So that when something goes wrong, the recovery procedures the README documents are real, not aspirational.

## Cluster & Findings

**Cluster D — must-fix (documented recovery paths dead).** Epic 10's fault-injection walk (retro §7) found the documented operator recovery paths broken:

- **F-10-6-3 HIGH** — `mailbot rederive` crashes on **every** invocation (`KeyError: no adapter registered for 'qwen2.5:3b-instruct-q4_K_M'`). `init_default_adapters()` is called by the FastAPI lifespan (`main.py`) and by `python -m …pipeline` (`pipeline.py`'s `init_pipeline_runtime`) but NEVER by the `rederive` CLI subcommand (`_cmd_rederive` calls only `_load_policy_for_cli()`). The documented recovery fix at README:295 (cross-ref :305) is dead. This ALSO blocks the 10-5-2 not-yet-classified refusal message, which was forbidden from suggesting `rederive` until it works.
- **F-10-6-2 MEDIUM** — move-induced `target_deleted` is NOT cleared by the documented `mailbot replay <id>` fix. `replay` re-queues the failed row unchanged; the drainer's `_check_tier_1` re-reads the same local soft-delete (`deleted_at IS NOT NULL`) and refuses again with `target_deleted`. Only 10-2 revert rows bypass (via `_is_revert_row` / `REVERT_OF_ACTION_ID_KEY`). README:307 replay clause is inert for this common case.
- **F5 HIGH + F6 HIGH** — move-family soft-delete has no resurrection path: a `MOVE_TO_TRIAGE_FOLDER` soft-deletes the local row (`removed_reason='deleted'` via delta sync, 10-1 walk F5), and `EMAIL_UPSERT` never resurrects it (F6). The retained 10-1 Railway walk subject is deliberately still soft-deleted as live F6 evidence (retro B5).
- **CR-10-2-D1 (deferred)** — legacy double-revert race: `revert_action` claims the revert via `ACTION_HISTORY_MARK_REVERTED` guarded by `reverted_at IS NULL`, but only when an `action_history` row exists. Legacy rows with no history row proceed unclaimed (residual race). Recorded in `deferred-work.md`.

See `10-6-walk-evidence.md` + `10-1-walk-evidence.md` + `10-2-walk-evidence.md` + `deferred-work.md`.
