- [LOW] The MCP wrapper for `cost_breakdown` uses `# type: ignore[arg-type]` to bridge the `Literal["today", "month"]` runtime expectation with the str-typed MCP tool parameter. Pydantic input-layer validation on the FastMCP side would catch wrong values before the underlying verb is invoked, but a manual `period not in ("today", "month")` check inside the wrapper would be more defensive. Accepted as-is for now — Story 5-2's pattern is "thin adapter; runtime validation happens at the underlying verb"; the underlying `cost_breakdown` has a `Literal` annotation and Pydantic's `model_validate` path would reject. The behavior is correct; the type-ignore is the cost of `Literal` not flowing through MCP's untyped JSON.

The `/label` command will register on Discord, but invoking it will hit a dispatcher gap until that work lands. Documented behavior.
