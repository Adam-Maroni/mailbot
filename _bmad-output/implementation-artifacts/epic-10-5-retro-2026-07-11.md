## 4. What went well (successes)

1. **Boundary-honesty as an epic-wide discipline** — the epic's signature behavior. 4 of 6 stories (10-5-2 skill-file, 10-5-3 digest, 10-5-5 spend-source, all of 10-5-6) refused to fabricate a `mailbot_api` fix for a problem that lived Hermes-side / in config / in deploy, and filed the follow-up instead. This is the exact inverse of the persona-prose-as-enforcement failure Epic 10 exposed. **Worth codifying as a rule.**
2. **The load-bearing gate clause closed clean** — authorization moved from persona prose to API enforcement, adversarially CR-verified (agent cannot self-authorize; confidential unconditionally refused; blast radius exact-scoped to (email, task) at SQL level).
3. **Cluster A killed the CRITICAL *and the bug class*** — pause + degraded now DB-authoritative cross-process. The "authoritative cross-process read" helper (`is_paused_now`/`is_degraded_now`, copied from `status.py:332`) became a reusable template consumed by 10-5-3, 10-5-5, 10-5-6.
4. **CR discipline held and improved under autonomous pressure** — near-100% apply-rate on all 6; reviewer severity *dropped* across the epic (10-5-2 caught a shipped functional regression; by 10-5-6 round 2 the reviewer found 0 HIGH/MEDIUM on a security-adjacent privacy seam). Evidence the dev's authorization-plumbing hygiene measurably improved.
5. **Estimator truth restored honestly, in the right order** — the load-bearing internal ordering (July re-derive before the footer) meant the first month-to-date figure a user ever saw was true (~$26, not the ~$70 inflated ledger).

## 5. What didn't (challenges / growth areas)

1. **"Wired + passing test" ≠ "reachable on the real user path."** The dominant defect class of the epic. 10-5-3 registered `draft_reply` and proved it with a legitimate green integration test — yet the live persona never called it (0 Opus rows in 3 walks). Same shape as F4 (drainer read a stale bool), F-10-6-3 (9 e2e tests blind to the real crash), and the qwen refusal (docstring asserts, nobody drives). **Lesson: a test that proves a tool EXISTS does not prove the persona REACHES it.**
2. **The mint-half / consume-half wiring gap hit twice** — 10-5-2 CR-3 (`record_grant_confirmation` had zero production callers → `mint_grant` permanently blocked) and 10-5-6 W2 (`escalation_armed` set + confirmation recorded, but the dispatch seam consulted neither). An authorization-plumbing smell: the two halves get built but never wired to each other.
3. **Persona self-narration** was the recurring live-walk failure class (4 walks: 10-5-1 W1, 10-5-2 W2, 10-5-6 W1, 10-5-6 W4). 10-5-6's recognized-phrase deterministic dispatch is the structural answer and works for cancel/pause/resume — but the escalation/draft path still leaks.
4. **Recurring CR themes** — race/TOCTOU on confirmation-consume seams (probed in 3 stories); guard/scope too broad → blast radius stays agent-controlled; the dev's pre-review self-audit was a reliable *finder* but an unreliable *dispositioner* (reviewer repeatedly overturned "accept-with-rationale" to "fix-now").

## 6. Significant discovery — architecture-integrity escalation (Adam-surfaced)

**Adam surfaced the deepest finding of the retro:** the founding cost thesis of the whole project — *an LLM assistant that functions without high cost* — structurally depends on a **local model that can call the pre-configured `mailbot_api` functions.** Tool-calling *is* how the cheap lane reaches those functions; that is the entire reason `mailbot_api` exists (push mailbox complexity into deterministic local functions, reserve paid cloud for irreducible reasoning).

Story 10-5-5 found the current local path fails **18/18 tool-call attempts** — `OllamaAdapter.call_with_tools` at [models.py:419](../../mailbot_api/router/models.py) unconditionally raises `tools_unsupported`. If the local lane genuinely cannot act, every real action-taking turn falls through to paid cloud and the cost thesis collapses. The 18/18 signal existed in the walk evidence but was never escalated to the founding-premise level until this retro.

**Key uncertainty (why this is a probe, not a panic):** the `tools_unsupported` docstring asserts *"Qwen 2.5 doesn't expose OpenAI-shape tool-calling at the inference surface we use"* — but that claim dates to Story 6-9 wiring and has never been re-tested. Qwen 2.5-Instruct and Ollama's `/v1/chat/completions` `tools` support have both moved since. The refusal may be a **stale write-off of the same "capability-dead-in-prose" class this epic existed to fix** — sitting in our own adapter code instead of the persona's.

**Hard constraint (Adam-decided):** any solution must run on the **local Ollama stack, same hardware, $0 marginal cost.** No cloud fallback on the default lane — that would dissolve the thesis.

### RE-TEST EXECUTED IN-RETRO (2026-07-11) — verdict: PASS (minor wiring fix, NOT a hard gate)

Adam directed the P0 re-test to run immediately. Probed the live `mailbot-ollama` container (Qwen 2.5 3B Q4_K_M) directly over HTTP:
- **Qwen 2.5 3B CAN tool-call on BOTH surfaces** — Ollama native `/api/chat` and OpenAI-compat `/v1/chat/completions` both return proper `tool_calls` blocks in the wire-shape the Router expects. **The `tools_unsupported` docstring is FALSE — a stale Story-6-9 write-off, the 5th instance of the epic's signature "capability-dead-in-prose" class, this time in our own adapter.**
- **Fidelity caveat:** Probe 1 (OpenAI-compat, default temperature) corrupted an argument — sent `ABC123`, got `ABC132`. But a 6-case sweep at **temperature 0** returned **6/6 exact on both surfaces** (incl. realistic ids). The corruption was a temperature setting, not a capability ceiling; the adapter already defaults to temp 0.

**Altitude resolved (per D5):** re-test PASSED → **minor wiring fix, no hard Epic 7 gate. The cost thesis survives.** AI-1 scope shifts from "can it tool-call?" (answered: yes) to "wire it + validate argument fidelity at scale before trusting it with real mailbox writes." No model swap or shim needed for basic tool-calling. Full evidence + revised scope: [AI-1-local-tool-caller-verify-or-restore.md](AI-1-local-tool-caller-verify-or-restore.md).

## 11. Key takeaways

1. **The dominant lesson: "wired + green test" ≠ "reachable on the real user path."** A test proving a capability exists is not a test proving the persona reaches it. This is the shared root of F4, F-10-6-3, F-10-5-11, and the qwen refusal.
2. **Boundary-honesty works and should be a rule** — refusing to fabricate a `mailbot_api` fix for a Hermes/config/deploy problem, and filing the follow-up, was the epic's best behavior. Codify it.
3. **The cheap local lane's ability to *act* is an architecture-integrity question, not a footnote** — it underpins the founding cost thesis and now gates Epic 7 pending a free re-test.
4. **CR discipline is durable under autonomous pressure** — reviewer ≠ dev, near-100% apply-rate, and dev hygiene measurably improved across the epic.
