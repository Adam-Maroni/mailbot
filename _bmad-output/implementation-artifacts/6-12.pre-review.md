## 3. Adversarial self-review

- **[LOW]** `tests/unit/router/test_anthropic_adapter.py:198` — `test_anthropic_adapter_live_opus_4_7_smoke` calls `pytest.skip(...)` inside the test body when `ANTHROPIC_API_KEY` is unset. This is a runtime skip, not a marker-based skip — meaning CI runners that opt-in with `-m live` but lack the API key will see the test appear in the run and skip-at-runtime rather than being deselected upfront. Functionally correct, but slightly less clean than gating via a fixture or env-marker. Acceptable per pytest convention.
- **[LOW]** `tests/unit/router/test_anthropic_adapter.py` — the 4 new regression tests duplicate the body shape of `test_anthropic_adapter_request_targets_correct_model_id` (lines 185-194). A parameterized test (`@pytest.mark.parametrize` over `model_id` × `expected_temperature_present`) would compress the 4 tests to ~30 lines instead of ~80. Trade-off: explicit-test-per-case is more readable when the assertions diverge (Opus asserts ABSENCE, Haiku asserts PRESENCE with exact value). Choice: kept the 4-test form for readability; flagging here so a reviewer can opt-in to parameterization if they prefer compression over explicitness.
- **[LOW]** `pyproject.toml:131` — `addopts = "-m 'not live'"` is a global default-exclusion. If a future story adds a new opt-out marker (e.g., `slow` already exists), the `addopts` string would need to grow to `-m 'not live and not slow'`. Manageable but worth flagging that the convention is now load-bearing for marker hygiene.
- **[LOW]** `tests/unit/router/test_anthropic_adapter.py:221` — `_trivial_tool()` helper builds a `ChatCompletionToolDef` with `parameters={"type": "object", "properties": {}}` — an empty JSON Schema. The Anthropic API translation in `_translate_tools_openai_to_anthropic` may or may not produce a valid `input_schema` for this shape (untested in this story). Risk: if Anthropic rejects empty-object schemas in `input_schema`, the `call_with_tools` regression tests would fail on the request-body assertion before even reaching the temperature check. Mitigated by `httpx.MockTransport` — the mock accepts any body and returns the canned response. Real-Anthropic call would surface this if it's actually a problem. Acceptable for unit-test scope.
- **[LOW]** `mailbot_api/router/models.py:559` + `:660` — the gate condition `self.model_id != "claude-opus-4-7"` is a string-literal compare. If Anthropic releases `claude-opus-4-7-20260601` (date-suffixed variant) or `claude-opus-4-8`, the gate would NOT match and `temperature` would leak again. A defensive widening to `not self.model_id.startswith("claude-opus-4-")` would future-proof — but also risks over-broad gating if Anthropic ships an Opus variant that DOES accept temperature. Trade-off: keep the exact literal for now (precision over future-proofing), surface to reviewer for opinion.
