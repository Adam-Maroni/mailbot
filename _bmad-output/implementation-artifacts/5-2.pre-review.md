## 3. Adversarial self-review

- [LOW] `mailbot_api/mcp_server.py:131-176` — every wrapper repeats the same `t0 = time.perf_counter() / try / log_crash / latency_ms / log_ok|log_error_as_data` boilerplate. Could be DRYed into a `_with_logging(tool_name, coro)` helper. Not shipping the refactor because (a) the explicit form is easier to scan when debugging a specific tool's dispatch, (b) 11 verbs is a manageable cap, (c) any abstraction would either need to know about the `ctx` parameter case (hydrate_email) or split into two helpers anyway.
- [MEDIUM] `mailbot_api/mcp_server.py:_session_id_from_ctx` — uses `id(ctx.session)` as the per-session key. This is process-local and not portable across MCP transport implementations (e.g., if the SDK ever wraps `ServerSession` in a proxy). The story Dev Notes acknowledged the SDK doesn't expose a stable session id in 1.27.2; `id()` was the documented fallback. Note for future MCP-SDK upgrades: if `Context` ever exposes a stable `session_id` property, swap to it.
- [LOW] `mailbot_api/mcp_server.py:_TOOL_DESCRIPTIONS` — descriptions are hand-written and could drift from the underlying verb docstrings. Future drift would not be caught by any automated check (the AC-1 constraint-phrase test only asserts the canonical phrases are present, not that the description matches the verb's actual docstring). Acceptable: agent-prompt-shaped text is intentionally curated, not auto-generated from internal-facing docstrings.
- [MEDIUM] `mailbot_api/main.py` — the per-lifespan FastMCP build allocates a new FastMCP + StreamableHTTPSessionManager on every uvicorn startup. In production this happens once per container start, so the cost is negligible. In tests, each `TestClient(app)` triggers a fresh build — measured ~0ms per test in the run (18 tests in 1.88s, dominated by SQLite migrations not FastMCP construction). No fix needed.
- [LOW] `tests/integration/test_mcp_server.py:_parse_tool_result` — accepts BOTH `structuredContent` and JSON-in-TextContent paths because the FastMCP SDK has both shipping concurrently. If 1.27.2 standardizes on one, the helper can simplify. Defensive ambiguity is correct for now.
- [LOW] `tests/integration/test_mcp_server.py::test_hydrate_email_30s_inactivity_resets_counter` — uses `monkeypatch.setattr(_mcp_mod, "datetime", _DT)` rather than `freezegun`. The hand-rolled fake works but is less idiomatic. Project does not currently depend on `freezegun`; not introducing a new test dep for one test.
- [MEDIUM] `scripts/check_boundaries.py` — the `_VERBS_IMPORT_ALLOW` is a hand-maintained list of 17 paths. Adding a new verb file requires remembering to update this allowlist OR the boundary check fails on the new file's own self-imports. Better: glob `mailbot_api/verbs/*.py` at script start. Deferred — minimal cost (every new verb touches `__init__.py` anyway, prompting the dev to check sibling files), and dynamic globbing introduces a new failure mode (mistyped path silently allowlisted).
- [LOW] `mailbot_api/mcp_server.py` — the 11 wrapper functions share a closure over `server_ctx`. If a future caller mistakenly builds two FastMCP servers with the same wrappers, the contexts would mix. Defensive: `build_mcp_server` always constructs a fresh `_ServerContext` per call (verified — `server_ctx = _ServerContext(db_path=db_path)` is inside the function body, not module-level). Safe.
