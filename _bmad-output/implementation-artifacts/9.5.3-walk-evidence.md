### F-FENCE-STRIP (P0, FIXED in-session)

**Symptom:** 100% of Anthropic-served structured-output tasks (`summary_short`, `importance_scoring`, `action_extraction`, `draft_reply`, `anchor_calibrated_eval`) failed with `outcome='failed'` across 500+ `router_calls` rows in the 3 days before this walk. Production ingest was silently non-functional for the entire Anthropic pipeline.

**Root cause:** Claude Haiku 4-5 and Opus 4-7 wrap JSON payloads in ```` ```json ... ``` ```` markdown code fences despite explicit prompt instructions ("Reply with valid JSON matching the schema; no preamble"). `mailbot_api/router/router.py:784+841` called `prompt.output_schema.model_validate_json(response.text)` on the fenced response; pydantic rejects it; both first attempt AND stricter-retry fail → `SCHEMA_VALIDATION_FAILED`.

**Fix shipped:** `_strip_code_fence()` helper in `router.py` (regex-based, tolerant of language tags + whitespace); wired at 2 parse sites (first-attempt + retry-leg; cache-read site skipped because that reads already-parsed JSON). +4 tests in `tests/unit/router/test_router.py` (fenced-first-attempt, bare-JSON regression, generic-triple-backtick, retry-leg-fenced).

**Live verification:** post-hotfix direct dispatch `ask_router("summary_short", ...)` → `ok=True cost=$0.0003 output=summary='Alice confirms Friday meeting.'`. Then AC-4 walk: 275/279 ok = 98.6% success rate.

**Impact scope:** load-bearing production bug. Every Anthropic-served ingest task was silently 100%-failing in prod audit rows before this walk landed the fix. This walk was the surface that surfaced it. **Recommend hotfix commit BEFORE Story 9.5.3 story-close** because production ingest pipeline is currently broken until this fix ships to the deployed container image (the walk injected via `docker cp` into the running container — a rebuild is needed to make the fix durable).

### F-RATE-LIMIT-CARVE-OUT (P1, FIXED in-session)

**Symptom:** AC-5 first attempt wrote 186 `provider_error` rows in 2 seconds with 0 successful dispatches. Story 9-6 runner does sequential dispatch through `ask_router` which enforces per-lane rate limits (60/hr interactive, 300/hr batch). `draft_reply` is `lane: interactive` — 186 cells burst instantly hit the 60/hr cap.

**Root cause:** `mailbot_api/router/limits.py:80-100` `enforce_rate_limit` had a `caller_origin="cache-warmer"` short-circuit but no analogous carve-out for `benchmark-runner` or `benchmark-scorer`. Benchmark walks are structurally incompatible with the interactive-lane cap.

**Fix shipped:** short-circuit added: `if caller_origin == "cache-warmer" or caller_origin.startswith("benchmark-"): return None`. +2 tests in `tests/unit/router/test_limits.py`.

**Live verification:** post-hotfix AC-5 retry #2 dispatched 186/186 cells to completion at 100% ok rate. Zero rate-limit refusals in run's `router_calls` audit trail.

**Impact scope:** any future benchmark walk without this carve-out cannot complete for interactive-lane tasks. This is a Story 9-6 CR-eligible defect (criterion 6 — load-bearing for benchmark instrument's usability); the runner's own tests never exercised the interactive-lane path.

### F-DRAFT-REPLY-CONTENT-SHAPE (P1, FIXED in-session)

### F-UNKNOWN-MODEL-COST-GATE (P0, NOT FIXED — root cause of $10-authorization overshoot)

**Symptom:** `benchmark.scorer` pre-flight printed `Estimated subjective-dispatch cost: $0.00` before dispatching 322 real Opus calls. I `--yes`-approved the run on that $0 estimate. Real dispatch cost: several dollars per the Anthropic Console reconciliation.

**Root cause:** `benchmark/scorer.py:62` has `_DEFAULT_SCORER_MODEL = "claude-opus-4-7-20251220"` — a model ID with a date suffix that is NOT registered as an adapter (registered opus is `claude-opus-4-7` per `pricing.py:40` + adapter registry). `pricing.py:56-60` `estimate_cost_usd()` returns 0.0 for unknown models (defensive fallback — "conservative: under-account a rogue caller"). The cost estimator uses `args.scorer_model` which was the bogus default; my `--scorer-model claude-opus-4-7` override was NOT reflected in the pre-flight estimate print because the estimate is computed BEFORE arg-based dispatch model resolution in the current code shape.

**Fix NOT shipped in-walk.** Correct fix has multiple components:
1. Correct `_DEFAULT_SCORER_MODEL` to `claude-opus-4-7` (5-second edit).
2. `estimate_cost_usd()` for unknown models should RAISE / return an error sentinel, NOT $0. The "conservative under-account" fallback that pricing.py explicitly cites (line 57-59) is EXACTLY the failure mode that caused this overshoot — a rogue caller with an unknown model ID silently costs whatever the actual dispatched model costs, because the estimator says $0 and the cost gate never fires. The safe default is "unknown model → refuse to dispatch, escalate for pricing correction."
3. The cost-gate print itself should include the source-of-pricing annotation: "Estimated $X.XX at placeholder pricing (pricing.py:15-16 warns real cost may differ)". Currently prints as if authoritative.

**Impact scope:** load-bearing for every benchmark walk with a paid scorer. This defect + the placeholder pricing (F-PLACEHOLDER-3X-DRIFT below) is the combined trust-failure vector for the $10 authorization breach.
