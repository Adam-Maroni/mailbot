## 3. Thread 1 — Hermes Runtime Mismatch (F3 / F4 / F5)

### What Phase 3.5 Section B uncovered

| Finding | Reality | Impact | Status |
|---|---|---|---|
| **F1** — `:ro` mount crashes Hermes container | Bind-mount `./hermes-config:/opt/data:ro` crashed Hermes at init with `OSError: [Errno 30] Read-only file system: '/opt/data/cron'`. Hermes treats `/opt/data` as HOME and needs to mkdir on first run. | Container never reached steady state. | **FIXED** — `:ro` flag dropped; runtime-write paths added to `.gitignore`; docker-compose shape test updated. |
| **F2** — MCP startup log hardcoded `tools=11` | Story 5-6 bumped `_EXPECTED_TOOL_COUNT` from 11 to 16 but missed the observability log line at `mailbot_api/main.py:222`. | Low-severity observability drift (Story 5-6 CR miss). | **FIXED** — log line now reads from `mailbot_api.mcp_server._EXPECTED_TOOL_COUNT`. |
| **F3** — Hermes image runs interactive TUI, not daemon | `nousresearch/hermes-agent:latest` default entrypoint runs the interactive `hermes` TUI; container splash-screens then exits on detached stdin. | Story 5-4's AR-DEPLOY-1 assumption ("treat image as daemon") is wrong. | **CARRY-FORWARD to Epic 6 Story 6-0.** |
| **F4** — `command:` override swallowed by s6 supervisor | `command: ["hermes", "gateway", "start"]` had no effect because the image is supervised by s6-overlay; the managed service `main-hermes` runs from `/etc/services.d/main-hermes/run`. Docker-level command overrides don't reach it. | Restart loop. Override was reverted; explicit comment left in `docker-compose.yml`. | **CARRY-FORWARD to Epic 6 Story 6-0.** |

Hermes's real schema lives at `hermes-agent.nousresearch.com/docs/user-guide/configuration` — never consulted. | Internally consistent YAML, but runtime contract with Hermes is hallucinated. Stories 5-5 (persona) + 5-6 (slash dispatch) ride on Hermes consuming this config. | **CARRY-FORWARD to Epic 6 Story 6-0.** |

### Root cause framing

The Story 5-4 Dev Notes *honestly hedged*: "verify against the image; Phase 3.5 catches the mismatch." Phase 3.5 caught it. The system worked as designed. **But the design tolerates a class of speculation that cost an epic's worth of integration work.**

> *"autonomous-epic-run is structurally vulnerable to it — it has no mechanism to consult external documentation, so it speculates and Phase 3.5 catches the speculation."* — `epic-5-run-flags.md` §"Recommendations for the next retrospective"

The right lesson is not "blame the speculation" — it's "Phase 3.5 IS the corrective; the speculation is bounded; Epic 6 closes it via real-docs consultation."

### Options considered and resolution

Three options were considered for resolving F3/F4/F5:

- **(A) Native install** — run Hermes natively per the README's PowerShell one-liner, learn the real schema interactively, port back. **Rejected by Adam** — breaks the docker-compose architecture (AR-DEPLOY-1), leaks debt into Epic 6 Story 6-7 (VPS deploy) and Epic 7 eval work.
- **(B) Probe the image** — `docker run --entrypoint sh` to read `/etc/services.d/main-hermes/run` and surrounding s6 service definitions. Tells us what the image *actually* does.
- **(C) Docs-archiver first** — mirror `hermes-agent.nousresearch.com/docs/` locally, read configuration + messaging + deployment + gateway + MCP pages. Tells us the *intended* contract.

**Decision: (C) then (B), as a single Epic 6 Story 6-0 corrective, with an Option (A) escape hatch.**

Rationale: (C) and (B) are complements, not rivals — (C) tells us the *intended* contract; (B) tells us the *actual* contract; the divergence is itself the finding. Sequencing (C) before (B) means we read with context instead of guessing what we're looking at.
