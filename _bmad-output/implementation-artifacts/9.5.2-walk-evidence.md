### AC-2 sequenced findings (three defect discoveries + one architectural fix)

#### Finding A — `policy.user-overrides.yaml` was a directory in the container (14:09 attempt)

The Docker single-file bind-mount source did not exist on the host, so Compose auto-created `/app/router/policy.user-overrides.yaml` as an **empty directory** on Jun 27 and it stayed that way. First `set_model_persistent` call returned:

> Error: The policy override file /app/router/policy.user-overrides.yaml is a directory, not a file. The router cannot read or write to it.

**Fix:** removed the host-side directory, `cp router/policy.user-overrides.yaml.example router/policy.user-overrides.yaml`, restarted `mailbot-api`. Container now sees a proper file.

#### Finding B — `os.replace` failed with `EBUSY` on single-file bind-mount (14:19 attempt)

After Finding A's fix, the next `set_model_persistent` call returned:

> Error: Atomic write to /app/router/policy.user-overrides.yaml failed — the device or resource is busy. The file is locked or in use.

Root cause: Docker bind-mounts pin the target inode. `os.replace(tmpfile, target)` in `write_user_overrides_atomic` at `mailbot_api/router/policy.py:429` cannot atomically rename across a bind-mount boundary — POSIX rename requires source and target to be on the same filesystem, and the bind-mount is a mount-namespace boundary. Reproducer confirmed inside the container:

```python
docker compose exec -T mailbot-api python -c "..."
# os.replace: FAILED errno=16 Device or resource busy
```

**Fix (Path B, Option 1):** changed docker-compose to bind-mount the whole `./router:/app/router` directory as read-write, with the file-level `:ro` overlay preserved on `policy.yaml` (Docker file-mounts take precedence over dir-mounts on the specific inode). Empirical verification:

```
C:\ on /app/router type 9p (rw, ...)
C:\ on /app/router/policy.yaml type 9p (ro, ...)
```

After the fix, `os.replace` succeeded and the read-only enforcement on `policy.yaml` remained active (write attempt failed with `Read-only file system`, preserving Story 9-4 AC-2 shipped-policy invariant).

#### Finding C — Hermes MCP session lost across `docker compose down mailbot-api` (14:24 attempt)

Every mailbot-api restart broke Hermes's MCP session. Hermes's retry envelope (5 attempts with backoff up to 16s) exceeded during container rebuild windows. Hermes recovered lazily on next user prompt without an explicit reconnect signal in stdout. Real Gateway log at `/opt/data/logs/gateways/default/current` inside the Hermes container shows the reconnection attempts; the s6 catch-log stdout stream did not.

**Workaround:** re-send Discord prompt after every mailbot-api restart. Hermes's next MCP tool invocation triggers a new handshake automatically.

#### Finding D — Layer-4 budget guard refuses opus-shaped Hermes-chat (14:35 attempt onward)

With the persistent override successfully written to `hermes_aux: model: claude-opus-4-7`, every subsequent Hermes-chat `chat_completions_tool_call` dispatch hit:

> HTTP 502 — estimated cost $0.55 exceeds per-call threshold $0.20

Hermes's context (~13,500 input tokens + 27 MCP tool schemas) × opus input pricing ≈ $0.55 estimated cost per call. Story 2-8 Layer-4 per-call budget guard refuses any single call over $0.20. This is the guard doing its job, not an AC-2 bug.

**Adam-decision:** accept as PARTIAL — the audit-invariant proof (`slash_command:persistent:adam` fires 6 times, atomic write succeeds, hot-reload works) is the L3 walk value. Budget-guard is orthogonal.
