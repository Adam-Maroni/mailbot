## 4. Why six all-green stories didn't move the goal — root cause

**The test rig ≠ production, and that gap was the whole ballgame.** The 10-7-0 spike's confident finding — "harness-fixable, no 3B ceiling; the `find_emails` description rewrite lifts leaf selection 0/20 → 20/20" — was measured against **direct-ollama drive on a curated menu**. It did **not** hold on the live Hermes Discord surface. Same model, same fix, different harness → different result.

Two compounding sub-causes:
1. **Attractor whack-a-mole.** We removed the *observed* attractor (`send_message` via `messaging`) but never enumerated the full peer set. The model simply jumped to the next attractor (`memory`), which was enabled the entire time.
2. **Load-bearing verification was sequenced LAST.** Four harness fixes shipped optimizing against a proxy; the one live walk that would have redirected them ran only at the end.

**Crucially — NO 3B ceiling is demonstrated.** Row 15095 shows qwen deriving the correct intent (`find_unread_emails`); it mis-*bound*, it didn't fail to comprehend. The fix is surface/binding, not a bigger model — 10-7-4 correctly stays closed-superseded.

### Post-retro addendum (2026-07-18) — action items 1+2 outcome + a new architecture finding

- **Action item 1 (Story 10.7.6) shipped + CR-clean; action item 2 (clause-3 re-walk) FAILED.** The `memory`-drop fixed SELECTION (memory 0 picks vs 9/11; qwen reaches `find_emails`) but the 2026-07-18 walk exposed a deeper defect: the turn RAN AWAY — ~60 `find_emails` calls on empty args over 26 min, no reply, escalated to the paid lane, 502'd (`F-10-7-6-R2`, BLOCKING). Clause 3 = REACHED-but-NOT-USABLE. Sequel story **10.7.7** drafted (turn-termination guard + fail-closed-at-$0 + the finding below). Epic 10.6 clause 3b stays open.
- **NEW FINDING — F-10-7-ARCH-1 (architecture / schema-completeness gap, Adam-surfaced 2026-07-18):** the root cause of the loop is that **`emails.is_read` was never captured.** Microsoft Graph exposes `isRead` on every message by default, and the sync worker persists sender/subject/date/etc. — but silently dropped the read/unread flag. So "find my unread emails" — a baseline inbox request — had **no backing query**, and the model looped trying to satisfy an unsatisfiable filter. This should have been caught at **ingest-design time** by the architect agent (schema-vs-domain-needs completeness review), not discovered via a 26-minute production loop months later. **Process amendment candidate for the NEXT retro:** add an explicit "does the persisted schema cover the obvious user-facing query verbs?" architect-agent gate at ingest/schema-design time — the same class of miss as an unvalidated live surface, one layer down (data model instead of tool surface). 10.7.7 AC-1 (path (a), Adam-pinned) closes the immediate gap by capturing `is_read`; the process gate is the durable fix.
