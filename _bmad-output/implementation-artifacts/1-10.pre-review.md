## 3. Adversarial self-review

- **[MEDIUM]** `sync_worker._resync_notification_fired` — module-level mutable state. Test isolation requires explicit reset (`sync_worker._resync_notification_fired = False`) at the start of each test that exercises the flag. If a future story adds a test that touches the 410 branch without resetting, that test will see whatever state the previous test left. Mitigation: tests explicitly reset; could be argued the flag should be wrapped in an instance/context object but for one-process-per-container that's overengineering.
- **[MEDIUM]** `_is_sync_state_not_found` does substring match (`"syncstatenotfound" in code.lower()`). This is intentional per AC-5 (docs don't pin casing) but is loose — a hypothetical Graph code "MailboxSyncStateNotFoundRecoverable" would match. Accept: known unknowns about Graph's error vocabulary mean tight equality could miss valid variants; substring + warning log is the right tradeoff.
- **[LOW]** `_extract_removed_reason` returns `str(reason)` if `reason` is truthy, but if Graph emits `reason: null` explicitly the `.get("reason")` returns None and we return None. If Graph emits `reason: ""` we treat it as falsy and return None. This drops the false-info-of-emptystring without distinguishing from absent. Accept: the column is nullable and the reverter treats NULL as "unknown" — fine.
- **[LOW]** `_handle_delta_token_invalidation` doesn't surface SQL or notification errors — both are awaited and assumed to succeed. If `execute_write` raises (e.g., DB locked), `run_once` will surface the exception to the worker loop, which is correct — but the debounce flag may not be set, causing the next 410 to re-notify. Acceptable: a DB-locked sync_state.delta_link UPDATE is a much bigger problem than duplicate notifications.
- **[LOW]** The 410 / 404 branches each duplicate the `SyncResult(...)` construction with `new_delta_link=None`. Could be extracted into a `_failed_sync_result(start, messages_seen, ...)` helper. Not done — explicit returns are clearer at this size.
- **[INFO]** `_make_message` test helper now emits `changeKey` by default. Any external test fixture file that hardcoded `@odata.etag`-only payloads will now hit the fallback warning path on replay. None known in this codebase.
- **[INFO]** `removed_reason` column is index 48 on `emails`. SQLite handles wide tables fine; just noting that any future raw-row-tuple consumer (we don't have any — everything goes through column-named SELECTs) would need updating.
